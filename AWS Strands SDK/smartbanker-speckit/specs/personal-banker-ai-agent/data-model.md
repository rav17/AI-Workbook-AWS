# Data Model: Personal Banker AI Agent

## Overview
The Personal Banker AI Agent uses a structured data model to represent users, interactions, financial patterns, tools, and recommendations. All entities are designed for efficient storage in AgentCore-managed memory and compatibility with AWS Bedrock embeddings.

## Entities

### UserProfile
Represents a customer's profile and preferences for personalized financial advice.

**Attributes:**
- `id` (string, required): Unique identifier for the user (e.g., customer ID from bank system).
- `risk_tolerance` (enum: low, medium, high): User's stated risk preference for investments.
- `savings_goal` (object): Target savings amount and timeline.
  - `amount` (number): Target amount in user's currency.
  - `timeline_months` (integer): Timeframe in months.
- `preferences` (object): User preferences for advice style.
  - `advice_style` (enum: conservative, balanced, aggressive): Preferred advice approach.
  - `communication_frequency` (enum: daily, weekly, monthly): How often to receive updates.
- `account_summary` (object): High-level account information (no sensitive raw data).
  - `total_balance` (number): Aggregated balance across accounts.
  - `account_types` (array of strings): Types of accounts (savings, checking, investment).
  - `last_updated` (datetime): When summary was last refreshed.

**Relationships:**
- One-to-many with InteractionRecord (user's interaction history).
- One-to-many with FinancialPattern (user's behavior patterns).

**Constraints:**
- `id` must be unique and immutable.
- Sensitive data (account numbers, transactions) not stored here.

### InteractionRecord
Records each user interaction for short-term memory and reflection.

**Attributes:**
- `id` (string, required): Unique interaction identifier.
- `timestamp` (datetime, required): When the interaction occurred.
- `intent` (string, required): User's intent (e.g., "analyze_spending", "get_savings_advice").
- `worker` (string, required): Which worker agent handled the request.
- `status` (enum: success, failure, required): Outcome of the interaction.
- `confidence` (number, 0.0-1.0): Agent's confidence in the recommendation.
- `outcome` (string): Summary of the recommendation or error.
- `issue_tags` (array of strings): Tags for issues encountered (e.g., "low_confidence", "compliance_violation").

**Relationships:**
- Many-to-one with UserProfile.

**Constraints:**
- Stored in short-term memory with automatic pruning.
- Prioritized by failure/low-confidence for retrieval.

### FinancialPattern
Semantic patterns extracted from user behavior for long-term memory.

**Attributes:**
- `semantic_embedding` (vector, required): AWS Bedrock embedding vector for similarity search.
- `description` (string, required): Human-readable description of the pattern.
- `outcome` (string, required): Result of applying this pattern (success/failure).
- `risk_level` (enum: low, medium, high): Associated risk level.
- `timestamp` (datetime, required): When the pattern was created/updated.

**Relationships:**
- Many-to-one with UserProfile.

**Constraints:**
- Stored in long-term semantic memory.
- Filtered to exclude patterns older than 365 days.
- Retrieved as top-K similarity matches only.

### ToolDefinition
Registry of available financial tools and their contracts.

**Attributes:**
- `name` (string, required): Tool identifier (e.g., "transaction_fetcher").
- `category` (enum: data_fetch, calculation, analysis, required): Tool type.
- `input_schema` (object, required): JSON schema for tool inputs.
- `output_schema` (object, required): JSON schema for tool outputs.
- `description` (string, required): Human-readable description.
- `allowed_intents` (array of strings): Which user intents can use this tool.

**Relationships:**
- Referenced by worker agents during tool selection.

**Constraints:**
- All tools exposed via AWS Lambda gateway.
- Input/output validation enforced.

### RecommendationReport
Structured output from worker agents.

**Attributes:**
- `status` (enum: success, failure, required): Overall status.
- `confidence` (number, 0.0-1.0, required): Confidence score.
- `recommendation` (string, required): The main advice or response.
- `risk_level` (enum: low, medium, high, required): Risk assessment.
- `issues` (array of objects): Any issues or caveats.
  - `type` (string): Issue type (e.g., "compliance", "eligibility").
  - `description` (string): Description of the issue.
- `rationale` (string): Explanation of how the recommendation was derived.

**Relationships:**
- Generated by worker agents.
- Stored as InteractionRecord.

**Constraints:**
- Must conform to strict JSON contract.
- Always includes risk labeling and disclaimers for medium/high risk.

## Data Flow
1. UserProfile loaded for personalization.
2. InteractionRecord created for each request.
3. FinancialPattern retrieved for context augmentation.
4. ToolDefinition validated before tool invocation.
5. RecommendationReport generated and stored as outcome.

## Storage Strategy
- UserProfile: Persistent in AgentCore (long-term).
- InteractionRecord: Short-term memory with bounded size (last N).
- FinancialPattern: Semantic memory with embedding search.
- ToolDefinition: Static registry in code.
- RecommendationReport: Stored as InteractionRecord outcome.
